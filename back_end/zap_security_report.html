🔍 ทำไมหน้าจอ ZAP ถึงยังขึ้น Alert 19 รายการ?

💡 สาเหตุหลัก: ZAP ไม่ได้ลบผลสแกนรอบเก่าทิ้ง (Session เก่ายังค้างอยู่)

ในโปรแกรม ZAP เมื่อกดสแกนซ้ำใน Session เดิม ("Untitled Session") โปรแกรมจะ เก็บ Alert เก่าไว้เสมอ ทำให้ข้อความเก่าอย่าง "CSP Header Not Set" และ "Missing Anti-clickjacking Header" ยังคงโชว์อยู่ ทั้งๆ ที่ในกรอบ Response Header ของคุณ เซิร์ฟเวอร์ส่ง Content-Security-Policy และ X-Frame-Options ไปแล้วอย่างถูกต้อง

ตารางวิเคราะห์สิ่งที่เกิดขึ้นจริง:

กลุ่ม Alert รายการ สถานะจริง คำอธิบาย
Alert เก่าที่ค้างอยู่ CSP Header Not Set, Missing Anti-clickjacking, HSTS Not Set, CORS, SRI ฯลฯ แก้ผ่านแล้ว เป็นผลจากการสแกนรอบแรกก่อน deploy เซิร์ฟเวอร์ส่ง Header ครบแล้ว แค่ ZAP ยังจำประวัติเก่าไว้
Alert ใหม่ (Low) Strict-Transport-Security Multiple Header Entries แก้แล้วใน app.py เกิดจาก Caddy และ Flask ใส่ HSTS ซ้ำกันทั้งคู่ ตอนนี้เอาออกจาก Flask แล้วเหลือ Caddy จุดเดียว
Alert ใหม่ (Medium) CSP: Failure to Define Directive with No Fallback แก้แล้ว เพิ่ม base-uri 'self'; form-action 'self' https://accounts.google.com; ครบถ้วน
Alert ใหม่ (Medium) CSP: Wildcard Directive แก้แล้ว เปลี่ยนจาก https: เป็นระบุโดเมน Google User Profile โดยเฉพาะ

🧹 วิธีรีเซ็ตเพื่อดูผลสแกนจริงในโปรแกรม OWASP ZAP

  • วิธีที่ 1 (แนะนำ): สร้าง Session ใหม่
    กดที่เมนู File > New Session ด้านบนซ้าย แล้วกด Start จะเป็นการล้างประวัติเก่าทิ้งทั้งหมด
  • วิธีที่ 2: ลบ Alert เก่าออก
    ที่แท็บ Alerts ด้านล่าง ให้ คลิกขวาที่โฟลเดอร์ Alerts > เลือก Delete All Alerts
  • จากนั้นกด Attack สแกนใหม่อีกครั้ง:
    ZAP จะประเมินเฉพาะการตอบสนองจริงของเซิร์ฟเวอร์ปัจจุบัน และ Alert เดิมทั้งหมดจะหายไปครับ!
